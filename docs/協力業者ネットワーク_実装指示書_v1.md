# 協力業者ネットワーク 実装指示書 v1

全業種対応・月額課金SaaS。既存の信用プラットフォーム（ashibaya-line）のドメイン層を拡張して構築する。

---

## 0. プロダクトの一行定義

> 仕事が見つかって、取った後の書類まで全部ここで終わる。

ツクリンク型のマッチングに、受発注・請求書・工事写真の実務機能を載せる。
**月額の対価はマッチングではなく実務機能**。案件がゼロの月でも使う理由があることを設計の最上位制約とする。

---

## 1. プラン設計

### 単一有料プラン（法人・個人同額）

| | 無料 | 有料 3,000円/月 |
|---|---|---|
| 会員登録・自社ページ | ○ | ○ |
| 案件一覧（概要のみ） | ○ | ○ |
| 案件詳細・応募・メッセージ | × | 無制限 |
| **受け取った注文書への注文請書返信** | **○** | ○ |
| **受け取った書類の閲覧・保管** | **○** | ○ |
| 注文書・契約書の発行 | × | 無制限 |
| 請求書の発行 | × | 無制限 |
| 工事写真 | 現場1件まで | 無制限 |

### 最重要ルール：受信・返信は無料、発行は有料

元請が注文書を送った相手が課金しないと返信できない設計だと、元請がこのアプリを使えない。
**受け取る側は常に無料**にすることで、有料会員1社が無料会員を引き込む導線になる。
引き込まれた無料会員は「自分が発注する側／請求する側」になった瞬間に課金する。

### クレジット制は採用しない

定額無制限。説明が1行で済むことを優先する。

## 2. 全業種対応の設計

足場依存になっているのは **組立/解体の2フェーズ** の部分のみ。
これを「独立して進行する作業トラック」の一般形として扱う。

### 業種マスタ

```
industries
  id
  name              -- 足場 / 塗装 / 内装 / 電気 / 解体 / 土木 / 建築 ...
  work_track_template  -- 既定の作業トラック構成
```

### 作業トラックのテンプレート例

| 業種 | 作業トラック |
|---|---|
| 足場 | 組立 / 解体（2トラック・独立進行） |
| 塗装 | 施工（1トラック） |
| 内装・電気 | 施工（1トラック） |
| 土木 | 工区ごとに可変（Nトラック） |

- トラック数は **可変** とし、`Transaction` 集約は `work_tracks[]` を持つ
- 既存の `billing_track`（出来高／一括）、是正・手直し、締め日／支払日は**全業種そのまま流用**
- `transaction.availableActions(role)` の単一ソース原則は維持する

### 会社プロフィール（全業種共通）

```
companies
  id, name, type(法人/個人事業主)
  industries[]          -- 複数業種の登録可
  service_areas[]       -- 都道府県／市区町村
  建設業許可番号, 許可業種, 有効期限
  社会保険加入状況（健保／厚年／雇用）
  労災上乗せ保険
  CCUS事業者ID（任意）
  信用レベル            -- 未認証 / Bronze / Silver / Gold / Platinum
```

> 許可番号と保険加入状況は必須項目にする。公共工事の施工体制台帳・再下請負通知書で
> 必ず要求されるため、ここを構造化して持っておくと後段の書類生成がそのまま組める。

## 3. 機能1：受発注＋請求書【最優先】

案件ゼロでも成立する唯一の機能。**ここから作る。**

### 絶対要件：アプリ外の取引でも使えること

アプリ内でマッチングした案件だけに限定しない。
普段付き合いのある元請との仕事、自分が下に出す仕事、全部この画面で書類を出せる。
→ 取引の起点を `project_id`（アプリ内案件）に**強制紐付けしない**。手入力の取引先で開始できること。

### 書類フロー

```
[見積書] → [注文書] → [注文請書] → （施工） → [出来高報告] → [請求書]
                ↑
          契約書（基本契約）は取引先ごとに1回
```

### データモデル

```
trade_partners        -- 取引先（アプリ内会員 or 手入力の外部業者）
  id, company_id(nullable), name, 担当者, 連絡先, 締め日, 支払日

contracts             -- 基本契約書
  id, from_company_id, to_partner_id, 契約日, 契約書PDF, 締結状態

orders                -- 注文書
  id, contract_id(nullable), 工事名, 工事場所, 工期, 請負代金,
  支払条件, 作業トラック構成, 状態(下書き/送信済/請書受領/完了)

order_acceptances     -- 注文請書
  id, order_id, 承諾日, 署名, 状態

invoices              -- 請求書
  id, order_id(nullable), 締め月, 明細[], 小計, 消費税, 合計,
  インボイス登録番号, 状態(下書き/送信済/入金済)
```

### 建設業法・電帳法まわりの実装要件

- **書面交付義務（建設業法19条）** の電子化要件を満たすこと
  - 相手方の**事前承諾**を取得・記録する
  - **見読性**：いつでもPDF出力・印刷できる
  - **原本性**：改ざん防止措置（電子署名＋タイムスタンプ、または送信後の編集不可＋監査ログ）
- **インボイス**：発行者の登録番号、税率区分ごとの合計、消費税額を必須項目に
- **電子帳簿保存法**：検索要件（取引年月日・取引先・金額）でインデックスを張る

### 画面

- 取引先一覧／登録
- 注文書 作成 → 送信 → 請書受領
- 受信ボックス（受け取った注文書・請求書。**無料会員もここは使える**）
- 請求書 作成 → 送信 → 入金消込
- 書類一覧（月別・取引先別、PDF一括ダウンロード）

## 4. 機能2：工事写真【民間工事向けに割り切る】

### v1のスコープ

- 撮影時に**電子黒板を合成**（工事名・工種・撮影箇所・略図・日付）
- 現場ごとにアルバム自動整理
- 撮影日時・位置情報を保持
- LINE／メールで共有、PDF台帳出力

### v1でやらないこと（明記）

**公共工事の電子納品には対応しない。**

公共工事で電子小黒板を使うには、CRYPTREC暗号リスト記載の技術による
信憑性確認（改ざん検知）機能の実装と、J-COMSIAの検定合格が必要。
納品時には信憑性チェック結果を監督職員に提出する運用も伴う。

→ 検定取得は独立プロジェクトとして扱う。v1では画面に
「公共工事の電子納品には未対応」と明示し、必要な業者は蔵衛門等を併用してもらう。

### データモデル

```
sites                 -- 現場
  id, order_id(nullable), 工事名, 場所, 工期

photos
  id, site_id, 撮影日時, 位置情報, 黒板情報(JSON), 元画像, 合成後画像,
  工種, 撮影箇所, ハッシュ値
```

> `ハッシュ値` は v1 では検定対象外だが、後から公共対応する際の土台として最初から保存しておく。

## 5. 機能3：案件一覧・応募・メッセージ

### 一覧に無料で出す項目

エリア／業種／規模（㎡・人工）／工期／支払サイト／発注者の信用レベル

### 有料で開く項目

現場住所／図面・現場資料／指値の金額／発注者の連絡先／メッセージ送信

### データモデル

```
projects              -- 案件
  id, posted_by_company_id, 業種, エリア, 規模, 工期,
  指値 or 見積依頼, 支払サイト, 現場資料[], 公開範囲, 状態

applications          -- 応募
  id, project_id, applicant_company_id, 見積金額, メッセージ, 状態

messages
  id, thread_id, from, to, body, 添付[]
```

### 成約後の接続

応募 → 成約したら、そのまま **機能1の `orders` を自動生成**する。
案件情報（工事名・場所・工期・金額）が注文書に流し込まれる。
ここが「探して終わり」のツクリンクとの決定的な差になる。

## 6. 実装順

| フェーズ | 内容 | 完了条件 |
|---|---|---|
| **P1** | 会社プロフィール／取引先／注文書・注文請書 | アプリ外の取引で注文書を発行・返信できる |
| **P2** | 請求書／受信ボックス／書類一覧 | 月末の請求業務が完結する |
| **P3** | 工事写真（民間向け） | 黒板合成→アルバム→PDF台帳出力 |
| **P4** | 案件一覧・応募・メッセージ | 案件投稿から応募まで一周する |
| **P5** | 成約→注文書の自動生成 | P4とP1が繋がる |
| **P6** | 課金（無料／3,000円の出し分け） | 決済とプラン制御 |

P1〜P2 の時点で単体の受発注ツールとして売れる状態にする。
マッチングが空でも会員が取れるかを、ここで検証できる。

## 7. 既存資産の流用ポイント

| 既存（ashibaya-line） | 本アプリでの扱い |
|---|---|
| `Transaction` 集約 | work_tracks を可変化して流用 |
| `billing track`（出来高／一括） | そのまま流用 |
| 是正・手直しループ | そのまま流用 |
| `availableActions(role)` | そのまま流用（全業種で共通） |
| 信用レベル | そのまま流用。全業種に開放 |
| 組立／解体の2フェーズ固定 | 業種テンプレートに置き換え |
| AshiBase 連携ポート | 足場業者のみ有効な任意機能に |
| 積算ツール | 見積書作成の入口として接続 |
