# ⑥ 元請視点の通し検証 v1

現在のプロトタイプを、**発注者（元請）として頭から一周**して確認した記録。
受注側の体験は概ね通っているが、発注側には穴が多い。

---

## 検証したシナリオ

工務店「高橋工業」が、市川の倉庫案件で足場屋を探し、発注し、支払うまで。

```
案件を投稿 → 応募が来る → 比較する → 選ぶ → 注文書 → 進捗を見る
→ 追加工事 → 請求を承認 → 支払う → 完了 → 次も頼む
```

---

## 見つかった問題

### 🔴 重大：応募を比較できない

**現状**：応募一覧はカードが縦に並ぶだけ。3社なら何とかなるが、8社来たら比較不能。

**元請が本当に見たいもの**
| 見たい | 現状 | 
|---|---|
| 金額の安い順 | ソートなし |
| 信用スコアの高い順 | ソートなし |
| 過去に使ったことがあるか | **表示なし** |
| 対応可能な日程 | メッセージを開かないと分からない |
| 応募を断る手段 | **ない** |

**必要な画面**：応募比較テーブル。
```
会社名        金額        信用   取引実績   着工可否
三和架設     1,240,000   Gold   初めて     9/5から○
東葛工業     1,180,000   Plat   3回        9/5から○
城東解体     1,350,000   Bronze 初めて     9/8から
```
横スクロールのテーブル。列タップでソート。**「過去の取引回数」が最重要**。

**「見送る」機能が必須**。断られないまま放置されるのが、
協力業者側にとって一番の不満になる。断ると相手に通知が飛ぶ形にする。

---

### 🔴 重大：複数の現場を横断して見る画面がない

**現状**：取引タブに取引が縦に並ぶだけ。

元請が10現場を回している場合、必要なのは
- 今週着工する現場はどれか
- 今日の日報が上がっていない現場はどれか
- 今月末に支払う金額の合計はいくらか
- 請書がまだ返ってきていないのはどれか

**必要な画面**：発注者ダッシュボード。

```
┌─ 今日 ─────────────────┐
│ 日報の未登録  3現場      │
│ 請書の未返送  1件        │
│ 承認待ちの請求 2件 ¥86万 │
└───────────────────────┘
┌─ 今月の支払 ───────────┐
│ 8/31  ¥1,240,000  4件   │
│ 9/30  ¥2,180,000  6件   │
└───────────────────────┘
```

これは**元請がプレミアムを払う理由**にもなる。
今のプランには「発注側にしか価値がない機能」が支払実績しかない。

---

### 🟡 中：支払予定の合計が分からない

**現状**：請求書が個別に並ぶだけで、月末にいくら払うのかが分からない。

元請の資金繰りは「今月末にいくら出るか」が全て。
承認済みの請求を**支払日ごとに合計**して見せる画面が要る。

CSV書き出しがあれば、そのまま振込データに使える。
これは地味だが、経理が毎月やっている作業をそのまま置き換えられる。

---

### 🟡 中：協力業者を「自社の名簿」として持てない

**現状**：会社一覧はプラットフォーム全体の検索。お気に入りはあるが、それだけ。

元請が欲しいのは**自社の協力業者名簿**。
- 職種ごとに分類（足場3社、塗装2社、電気1社…）
- それぞれの単価の記録
- 前回いつ使ったか
- 使わなくなった理由のメモ

「取引先」は今アプリ外の書類用にしかない。
**アプリ内の会社もここに束ねるべき**。

---

### 🟡 中：同じ内容で別の会社に発注できない

**現状**：注文書は毎回ゼロから入力。

倉庫の足場を毎年3棟建てる元請は、**去年と同じ内容**を使いたい。
- 過去の注文書を複製して新規作成
- テンプレートとして保存

これがないと、発注が増えるほど入力が苦痛になる。

---

### 🟡 中：見積依頼を複数社に一斉送信できない

**現状**：スカウトは1社ずつ送る。

相見積もりを取るのが元請の普通の動き。
「この案件で、この5社に見積依頼」を一度に送れないと使われない。

スカウト送信の枠を消費する数は同じでいいので、**送信操作をまとめる**。

---

### 🟢 軽：発注側から日報にコメントできない

日報を見て「北面の写真も撮っておいて」と伝えたい。
今はメッセージに移動する必要がある。日報にひとことコメントできると、
現場のやり取りが日報に集約される。

---

### 🟢 軽：注文書のPDFに自社ロゴ・印影が入らない

元請は自社の様式で出したい。ロゴと社判の画像を設定できるだけで、
「ちゃんとした会社の書類」に見える。地味に効く。

---

### 🟢 軽：完了承認したあとに何も起きない

取引が完了しても、次のアクションへの導線がない。
- この会社を協力業者名簿に登録する
- 次の案件でも声を掛ける
- 工事写真の台帳をまとめて書き出す

**完了直後は満足度が最も高い瞬間**。ここで次に繋げないと、また探すところからになる。

## 発注側に足りていない画面（まとめ）

| 優先 | 画面 | 内容 |
|---|---|---|
| **高** | 発注者ダッシュボード | 未対応・今週の予定・今月の支払 |
| **高** | 応募比較テーブル | ソート・過去取引・見送り機能 |
| **高** | 支払予定一覧 | 支払日ごとの合計・CSV書き出し |
| 中 | 協力業者名簿 | 職種別・単価履歴・最終取引日 |
| 中 | 注文書の複製／テンプレート | 過去の注文書から作る |
| 中 | 見積依頼の一斉送信 | 複数社を選んで同時に送る |
| 低 | 日報へのコメント | 現場のやり取りを日報に集約 |
| 低 | 書類の様式設定 | ロゴ・印影・自社様式 |
| 低 | 完了後の導線 | 名簿登録・台帳出力・次の依頼 |

## この検証から見えた構造的な話

**このアプリは今、受注側のアプリになっている。**

機能を数えると、受注側向けが圧倒的に多い。

| | 受注側 | 発注側 |
|---|---|---|
| 案件を探す・応募 | ○ | — |
| 空き情報を出す | ○ | — |
| 工事写真・日報 | ○ | 見るだけ |
| 請求を出す | ○ | — |
| 信用を積む | ○ | — |
| スカウトを送る | — | ○ |
| 注文書を出す | — | ○ |
| 支払実績を見る | — | ○ |

**発注側の機能は3つしかない。** これは問題です。理由は2つ。

**1. 元請がいないとマーケットが成立しない。**
案件を出すのも、スカウトを送るのも、注文書を出すのも元請です。
元請が定着しないと、協力業者側の価値（案件が来る）が生まれません。

**2. 単価が高いのは元請。**
月1万円を払えるのは元請専業か中規模以上です。
その層に刺さる機能が「支払実績が見える」だけでは弱い。

**ダッシュボードと応募比較と支払予定一覧の3つは、
元請専用の価値として作る意味があります。** 
「発注管理ツールとしても使える」という売り方ができるようになる。

---

## 提案：次にやるなら

受注側の機能をこれ以上増やすより、**発注側を3画面足す**方が効きます。

1. 発注者ダッシュボード
2. 応募比較テーブル（＋見送り）
3. 支払予定一覧（＋CSV）

この3つで、元請が毎日開く理由ができます。
元請が毎日開けば案件が出て、案件が出れば協力業者が集まる。
順序として、こちらが先だと思います。
